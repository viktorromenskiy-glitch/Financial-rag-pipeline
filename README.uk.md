Financial RAG Pipeline

RAG-конвеєр для питань-відповідей над фінансовими документами (текст + таблиці). Гібридний пошук, контекстне збагачення, реранжування та оцінка через LLM-суддю — побудовано і протестовано на 7300+ реальних фінансових документах, що вимагають точних числових відповідей.

Статус: у розробці. Архітектура і всі ключові рішення зафіксовані та підкріплені вимірюваннями (див. нижче); реалізація ще триває. Цей README буде оновлено фінальними наскрізними результатами після того, як весь пайплайн буде закодовано і оцінено (див. Відомі обмеження).

Чому саме цей проєкт

Більшість публічних RAG-демо працюють з чистим текстом (Wikipedia, блоги, документація). Фінансові документи — складніший і реалістичніший тест: змішаний текст і таблиці, точні числові відповіді, де «приблизно» не рахується, і висока ціна помилки. Проєкт використовує T²-RAGBench — об'єднання FinQA, ConvFinQA і TAT-DQA — 7318 документів і 23088 питань, що вимагають точних числових обчислень над текстово-табличними фінансовими документами.

Архітектура
Ingestion (FinQA + ConvFinQA + TAT-DQA)
  → Chunking (один документ = один чанк)
  → Contextual enrichment (Claude Haiku 4.5, опційно, конфіг-флаг)
  → Embedding (Voyage-4, ембедить збагачений текст, якщо enrichment увімкнено)
  → Indexing (MongoDB Atlas: векторний індекс + повнотекстовий індекс)
  → Hybrid retrieval ($rankFusion: BM25 + dense, топ-50)
  → Reranking (Cohere Rerank v4.0 Pro, опційно, повний текст, топ-5)
  → Generation (прямa відповідь, Claude Sonnet 5, формат, інваріантний до знаку/масштабу)
  → LLM Judge Evaluation (суддя Claude Sonnet 5 + детермінована числова перевірка)

Кожен компонент (reranker, enrichment, модель судді, модель ембеддингу, розмір пулу) перемикається через конфіг, не захардкожено — див. config/config.yaml.

Ключові рішення — підкріплені вимірюваннями, не інтуїцією

Кожне число нижче має пряме посилання на конкретний тест, повністю задокументований у docs/poshagovyi_plan_vypolneniya.md (повний журнал експериментів) і docs/tehnicheskoe_zadanie.md (фінальна специфікація).

Критерій готовності: baseline-relative (статистично значуще покращення відносно власного baseline проєкту через paired bootstrap/McNemar), не довільна фіксована планка метрики.

Датасет

T²-RAGBench — об'єднання FinQA, ConvFinQA і TAT-DQA. 7318 документів (текст + таблиці), 23088 питань. Обрано саме через складність і реалістичність: точні числа, змішаний текстово-табличний формат, висока ціна помилки.

Відомі обмеження (чесний статус)
Ще не підтверджено на повному масштабі: ефект contextual enrichment (+0.78 в.п.) і його комбінація з reranker'ом (Recall@5 = 0.980) виміряні на зменшеній підвибірці в 450 документів, не на повному корпусі з 7318. Наскрізний прогін на повному корпусі запланований для підтвердження або перегляду цих чисел, перш ніж вважати їх фінальними.
Результати на малих вибірках: порівняння формату генерації і згода судді базуються на n=30 — достатньо, щоб виявити великий ефект, недостатньо, щоб виключити малий.
Цей проєкт повідомляє числа так, як вони реально виміряні, включно з розміром вибірки і тим, що ще відкрито — не як відшліфоване твердження про завершену, повністю перевірену систему.
