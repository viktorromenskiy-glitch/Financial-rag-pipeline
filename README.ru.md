Financial RAG Pipeline

RAG-конвейер для ответов на вопросы по финансовым документам (текст + таблицы). Гибридный поиск, контекстное обогащение, реранжирование и оценка через LLM-судью — построено и протестировано на 7300+ реальных финансовых документах, требующих точных числовых ответов.

Статус: в разработке. Архитектура и все ключевые решения зафиксированы и подкреплены измерениями (см. ниже); реализация ещё в процессе. Этот README будет обновлён финальными сквозными результатами после того, как весь пайплайн будет закодирован и оценён (см. Известные ограничения).

Почему именно этот проект

Большинство публичных RAG-демо работают с чистым текстом (Wikipedia, блоги, документация). Финансовые документы — более сложный и реалистичный тест: смешанный текст и таблицы, точные числовые ответы, где «приблизительно» не считается, и высокая цена ошибки. Проект использует T²-RAGBench — объединение FinQA, ConvFinQA и TAT-DQA — 7318 документов и 23088 вопросов, требующих точных числовых вычислений над текстово-табличными финансовыми документами.

Архитектура
Ingestion (FinQA + ConvFinQA + TAT-DQA)
  → Chunking (один документ = один чанк)
  → Contextual enrichment (Claude Haiku 4.5, опционально, конфиг-флаг)
  → Embedding (Voyage-4, эмбеддит обогащённый текст, если enrichment включён)
  → Indexing (MongoDB Atlas: векторный индекс + полнотекстовый индекс)
  → Hybrid retrieval ($rankFusion: BM25 + dense, топ-50)
  → Reranking (Cohere Rerank v4.0 Pro, опционально, полный текст, топ-5)
  → Generation (прямой ответ, Claude Sonnet 5, формат, инвариантный к знаку/масштабу)
  → LLM Judge Evaluation (судья Claude Sonnet 5 + детерминированная числовая проверка)

Каждый компонент (reranker, enrichment, модель судьи, модель эмбеддинга, размер пула) переключается через конфиг, не захардкожен — см. config/config.yaml.

Ключевые решения — подкреплены измерениями, не интуицией

Каждое число ниже имеет прямую ссылку на конкретный тест, полностью задокументированный в docs/poshagovyi_plan_vypolneniya.md (полный журнал экспериментов) и docs/tehnicheskoe_zadanie.md (финальная спецификация).

Критерий готовности: baseline-relative (статистически значимое улучшение относительно собственного baseline проекта через paired bootstrap/McNemar), не произвольная фиксированная планка метрики.

Датасет

T²-RAGBench — объединение FinQA, ConvFinQA и TAT-DQA. 7318 документов (текст + таблицы), 23088 вопросов. Выбран именно за сложность и реалистичность: точные числа, смешанный текстово-табличный формат, высокая цена ошибки.

Известные ограничения (честный статус)
Ещё не подтверждено на полном масштабе: эффект contextual enrichment (+0.78 п.п.) и его комбинация с reranker'ом (Recall@5 = 0.980) измерены на уменьшенной подвыборке в 450 документов, не на полном корпусе из 7318. Сквозной прогон на полном корпусе запланирован для подтверждения или пересмотра этих чисел, прежде чем считать их финальными.
Результаты на малых выборках: сравнение формата генерации и согласие судьи основаны на n=30 — достаточно, чтобы обнаружить большой эффект, недостаточно, чтобы исключить малый.
Этот проект сообщает числа так, как они реально измерены, включая размер выборки и то, что ещё открыто — не как отполированное утверждение о законченной, полностью проверенной системе.
